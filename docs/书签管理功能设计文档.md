# 书签管理功能设计文档

## 1. 概述

书签管理（网页收藏）是 Spy-Look 的一个内置工具模块，提供独立于浏览器的网页书签集中管理能力。用户可以在一个统一的界面中收藏、组织、搜索和快速访问常用网页链接。

**设计目标：**
- 轻量级，零外部依赖（纯内部管理，不依赖第三方书签服务）
- 全局共享，多设备共用一个书签库
- 扁平分组 + 多对多标签，灵活组织
- 基于访问频率的智能 TOP5 推荐
- 置顶功能保证常用书签始终可见

## 2. 表结构设计

### 2.1 SpyLookBookmarkGroup（书签分组）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTO | 主键 |
| name | VARCHAR | UNIQUE, INDEX, NOT NULL | 分组名称，全局唯一 |
| sort_order | INTEGER | DEFAULT 0 | 排序序号 |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

**设计说明：**
- 扁平分组，不支持嵌套层级
- `name` 全局唯一约束保证分组名不重复
- `sort_order` 控制前端侧边栏显示顺序

### 2.2 SpyLookBookmarkTag（书签标签）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTO | 主键 |
| name | VARCHAR | UNIQUE, INDEX, NOT NULL | 标签名称，全局唯一 |
| color | VARCHAR | DEFAULT '#64748b' | 标签颜色（十六进制色值） |
| created_at | DATETIME | NOT NULL | 创建时间 |

**设计说明：**
- 标签是全局共享的，不归属某个用户或分组
- 标签颜色用于前端显示区分

### 2.3 SpyLookBookmarkTagLink（书签-标签多对多关联表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| bookmark_id | INTEGER | PK, FK → spy_look_bookmarks.id | 书签 ID |
| tag_id | INTEGER | PK, FK → spy_look_bookmark_tags.id | 标签 ID |

**设计说明：**
- 联合主键实现多对多关联
- 删除书签时级联删除关联记录

### 2.4 SpyLookBookmark（书签主表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTO | 主键 |
| url | VARCHAR | UNIQUE, INDEX, NOT NULL | 归一化后的 URL，全局唯一 |
| title | VARCHAR | DEFAULT '', INDEX | 网页标题 |
| favicon_url | VARCHAR | DEFAULT '' | 图标 URL |
| group_id | INTEGER | FK → spy_look_bookmark_groups.id, NULLABLE, INDEX | 所属分组（NULL 表示未分组） |
| pinned | BOOLEAN | DEFAULT FALSE, INDEX | 是否置顶 |
| access_count | INTEGER | DEFAULT 0 | 累计访问次数 |
| last_accessed_at | DATETIME | NULLABLE | 最近访问时间 |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

**设计说明：**
- `url` 的唯一约束基于**归一化后的 URL**，而不是原始字符串
- `pinned` 字段加索引，支持高效的置顶书签查询
- `group_id` 为 NULL 时视为"未分组"
- 反范式化设计：`access_count` 和 `last_accessed_at` 是冗余字段，通过访问日志实时更新，避免每次查询都计算

### 2.5 SpyLookBookmarkAccessLog（访问日志）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTO | 主键 |
| bookmark_id | INTEGER | FK → spy_look_bookmarks.id, INDEX, NOT NULL | 书签 ID |
| accessed_at | DATETIME | INDEX, NOT NULL | 访问时间 |

**设计说明：**
- 每访问一次书签就插入一条记录
- `accessed_at` 加索引，支持 7 天时间窗口高效查询
- 定期清理 30 天前的旧日志，防止表无限膨胀

## 3. URL 归一化策略

**函数：** `normalize_url(raw: str) -> str`

为确保 URL 唯一约束的有效性，入库前对 URL 执行以下归一化处理：

1. **补充协议头：** 不带 `://` 的 URL 自动补 `https://`
2. **小写化：** scheme 和 host 转为小写
3. **移除默认端口：** `http:80` 和 `https:443` 的端口部分被移除
4. **路径规范化：**
   - 根路径 `/` 转为空字符串
   - 非根路径移除尾部斜杠 `/`
5. **丢弃 query 和 fragment：** `?` 和 `#` 及之后的内容被丢弃

**示例：**

| 原始 URL | 归一化后 |
|----------|----------|
| `https://Example.com/` | `https://example.com` |
| `https://example.com:443/path/` | `https://example.com/path` |
| `HTTP://EXAMPLE.COM:80` | `http://example.com` |
| `example.com?foo=bar` | `https://example.com` |

**注意：** `www` 和非 `www` 视为不同域名，不做归一化（如 `www.example.com` ≠ `example.com`）。

## 4. API 接口设计

所有接口路径均以 `/bookmarks/admin` 为前缀，受 `ConsoleAuthMiddleware` 认证保护。

### 4.1 分组管理

| 方法 | 路径 | 说明 | 请求体 |
|------|------|------|--------|
| GET | `/groups` | 获取全部分组（含书签数） | - |
| POST | `/groups` | 创建分组 | `{ name, sort_order? }` |
| POST/PUT | `/groups/{id}` | 修改分组 | `{ name?, sort_order? }` |
| DELETE | `/groups/{id}` | 删除分组（非空则拒绝） | - |

### 4.2 标签管理

| 方法 | 路径 | 说明 | 请求体 |
|------|------|------|--------|
| GET | `/tags` | 获取全部标签 | - |
| POST | `/tags` | 创建标签 | `{ name, color? }` |
| POST/PUT | `/tags/{id}` | 修改标签 | `{ name?, color? }` |
| DELETE | `/tags/{id}` | 删除标签 | - |

### 4.3 书签管理

| 方法 | 路径 | 说明 | 请求体 / 参数 |
|------|------|------|--------|
| GET | `/bookmarks` | 获取书签列表（支持筛选） | `q`, `group_id`, `tag_ids`, `pinned_only` query 参数 |
| GET | `/bookmarks/top5` | 获取近 7 天 TOP5 书签 | - |
| GET | `/bookmarks/{id}` | 获取单个书签详情 | - |
| POST | `/bookmarks` | 创建书签 | `{ url, title?, favicon_url?, group_id? }` |
| POST | `/bookmarks/fetch-metadata` | 抓取页面元信息 | `{ url }` → 返回 `{ title, favicon_url }` |
| POST/PUT | `/bookmarks/{id}` | 更新书签 | `{ title?, favicon_url?, group_id?, pinned? }` |
| DELETE | `/bookmarks/{id}` | 删除书签 | - |
| POST | `/bookmarks/{id}/access` | 记录访问 + 计数 | - |
| POST/PUT | `/bookmarks/{id}/tags` | 设置书签标签（全量替换） | `{ tag_ids: [] }` |

**认证说明：** 除 `/bookmarks/admin/bookmarks/fetch-metadata` 外，所有接口均需通过 Cookie Session 认证。未认证请求返回 401。

## 5. TOP5 算法

**计算逻辑：**

1. 取当前时间往前 7 天作为时间窗口
2. JOIN `spy_look_bookmarks` 和 `spy_look_bookmark_access_logs`
3. 按 `accessed_at >= cutoff` 过滤
4. `GROUP BY bookmark.id` + `ORDER BY COUNT(*) DESC`
5. `LIMIT 5` 取前五条

**返回数据：** 每条书签额外附带 `access_count_7d` 字段（近 7 天访问次数）。

**日志清理：** 服务启动时在后台触发一次清理，删除 30 天前的访问日志（保留 30 天为 7 天 TOP5 计算提供充足数据窗口）。

**注意：** TOP5 基于独立 7 天时间窗口计算，同一书签可在不同周期重复上榜。

### 6.2 视图模式

支持**卡片视图**和**列表视图**两种布局，通过右上角按钮切换，偏好存储在 `localStorage`（key: `bm-view-mode`）。

### 6.3 交互逻辑

**添加书签流程：**
1. 点击「添加书签」打开弹窗
2. 输入 URL，点击「抓取」按钮
3. 后端异步抓取页面标题和 favicon，自动填充
4. 用户确认/修改标题，选择分组和标签
5. 点击「保存」提交

**打开书签：**
1. 点击书签卡片/行 → `window.open(url, '_blank', 'noopener,noreferrer')`
2. 同时以 fire-and-forget 方式调用 `POST /bookmarks/{id}/access` 记录访问
3. 乐观更新本地 `access_count`，后台刷新 TOP5 和置顶列表

**置顶切换：**
- 点击书签上的图钉图标 `📌` 切换置顶状态
- 置顶书签始终显示在置顶区，不受分组筛选影响
- `pinned_only=true` 参数专门用于获取置顶列表

**分组筛选：**
- 侧边栏点击"全部书签" → 不过滤
- 点击具体分组名 → 按 `group_id` 过滤
- 点击"未分组" → 前端过滤 `group_id IS NULL`

**标签筛选（OR 逻辑）：**
- 点击标签芯片切换激活状态
- 选中多个标签时，返回命中**任一**标签的书签（OR 逻辑）
- 取消所有标签则不过滤

**搜索：**
- 300ms 防抖输入，搜索标题和 URL（不区分大小写）
- 搜索与分组/标签筛选可叠加

**删除保护：**
- 删除书签前弹出确认对话框
- 删除分组时，如果分组下还有书签则拒绝操作

### 6.4 前端的模块级单例

前端使用函数式单例模式管理状态（不使用 Pinia/Vuex），三个独立的 composable：

| Composable | 管理状态 | 主要方法 |
|------------|----------|----------|
| `useGroups()` | `_groups` ref | `listGroups`, `createGroup`, `updateGroup`, `deleteGroup` |
| `useTags()` | `_tags` ref | `listTags`, `createTag`, `updateTag`, `deleteTag` |
| `useBookmarks()` | `_bookmarks`, `_pinned`, `_top5` refs | `listBookmarks`, `listPinned`, `getTop5`, `createBookmark`, `updateBookmark`, `deleteBookmark`, `setBookmarkTags`, `recordAccess`, `fetchMetadata` |

每个 composable 的 CRUD 方法在完成后自动刷新对应的 ref，保证数据一致性。

## 7. 认证与安全

- 所有 `/bookmarks/admin/*` 路径注册在 `MANAGEMENT_PREFIXES` 中，受 `ConsoleAuthMiddleware` 保护
- 前端通过 Cookie Session（`spy_look_session`）认证
- Vite 开发模式下通过 `proxy` 将 `/bookmarks/admin` 请求转发到后端 8000 端口
