# 算法练习功能设计文档

## 1. 概述

算法练习（Algorithm Practice）是 Spy-Look 的一个内置工具模块，提供个人算法题的创建、练习与沉淀能力。用户可以在统一界面中新建算法题（标题 + Markdown 描述 + 标签），在分屏页面中编写 Python 代码实时运行调试，记录解题思路，并支持按标签筛选回看历史题目。

**设计目标：**
- 轻量级，复用项目既有 FastAPI + SQLModel + Vue 3 技术栈，不引入新框架
- 自由运行模式：不判定对错，运行代码看 stdout/stderr，适合探索性练习和调试
- 代码与思路同题保存，方便后续回看
- 独立标签池：算法题标签与书签标签互不干扰
- 编辑器内实时语法检查，错误即时反馈
- 本地个人工具，单用户场景，安全策略以「子进程 + 超时 + 隔离模式」为主

**核心流程：** 题目列表 → 新建/选择题目 → 练习页写代码 → 运行调试 → 保存代码+思路 → 打标签归档 → 列表筛选回看

## 2. 表结构设计

新增 3 张表，均以 `spy_look_algorithm_` 为前缀，定义于 `api/db/models.py` 末尾，由 `init_db()` 自动建表（无迁移系统）。

### 2.1 SpyLookAlgorithmProblem（算法题主表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTO | 主键 |
| title | VARCHAR | INDEX, NOT NULL | 题目标题 |
| description | TEXT | NOT NULL, DEFAULT '' | 题目描述（Markdown 格式） |
| solution_code | TEXT | NOT NULL, DEFAULT '' | 用户保存的解题代码（单份，覆盖式保存） |
| thought | TEXT | NOT NULL, DEFAULT '' | 解题思路（单字段文本） |
| created_at | DATETIME | NOT NULL | 创建时间 |
| updated_at | DATETIME | NOT NULL | 更新时间 |

**设计说明：**
- 描述采用 Markdown 存储，前端复用 `renderMarkdownHtml` 渲染（含代码高亮）
- 代码与思路均存于题目表内，无独立版本快照（需求确认：单份手动保存）
- `updated_at` 在每次更新（含保存代码、设置标签）时刷新，用于列表默认排序

### 2.2 SpyLookAlgorithmTag（算法题标签）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTO | 主键 |
| name | VARCHAR | UNIQUE, INDEX, NOT NULL | 标签名称，全局唯一 |
| color | VARCHAR | DEFAULT '#64748b' | 标签颜色（十六进制色值） |
| created_at | DATETIME | NOT NULL | 创建时间 |

**设计说明：**
- 独立标签池，与书签标签（`spy_look_bookmark_tags`）完全分离
- 标签可单独创建/删除，删除时级联清理关联记录

### 2.3 SpyLookAlgorithmTagLink（题目-标签多对多关联表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| problem_id | INTEGER | PK, FK → spy_look_algorithm_problems.id | 题目 ID |
| tag_id | INTEGER | PK, FK → spy_look_algorithm_tags.id, INDEX | 标签 ID |

**设计说明：**
- 联合主键实现多对多关联
- 删除题目/标签时均需先清理本表关联记录（见数据访问层）

## 3. API 接口设计

所有端点前缀为 `/algorithm/admin`，由 `api/tools/algorithm_practice/router.py` 聚合三个子路由并注册到 `api/main.py`。请求模型（Pydantic BaseModel）定义于 `schemas.py`，所有响应为 `JSONResponse`，错误统一走 FastAPI `HTTPException`（400 参数错误 / 404 资源不存在）。

### 3.1 题目路由（routes/problems.py）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /problems | 题目列表（支持 q / tag_ids / sort 查询参数） |
| GET | /problems/{problem_id} | 题目详情（含 description、solution_code、thought、tags） |
| POST | /problems | 创建题目（CreateProblemRequest：title 必填，description/tag_ids 可选） |
| POST+PUT | /problems/{problem_id} | 更新题目（UpdateProblemRequest：所有字段可选，保存代码+思路走此接口） |
| DELETE | /problems/{problem_id} | 删除题目 |
| POST+PUT | /problems/{problem_id}/tags | 设置题目标签（SetProblemTagsRequest，全量替换） |

**查询参数：**
- `q`：标题模糊搜索（`ilike` 匹配）
- `tag_ids`：逗号分隔的标签 ID 列表，多标签取交集（内连接 + distinct）
- `sort`：`updated_desc`（默认，最近更新在前）/ `updated_asc` / `created_desc`

**列表轻量化：** 列表接口不返回完整 description/code/thought，仅返回 `description_preview`（前 200 字符），供列表悬浮预览使用，减少传输量。

### 3.2 标签路由（routes/tags.py）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /tags | 标签列表（按名称排序） |
| POST | /tags | 创建标签（CreateTagRequest：name 必填，color 默认 #64748b；重名报 400） |
| POST+PUT | /tags/{tag_id} | 更新标签（UpdateTagRequest：name/color 可选） |
| DELETE | /tags/{tag_id} | 删除标签（先清理关联记录） |

### 3.3 执行路由（routes/execution.py）

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /execute | 执行 Python 代码（ExecuteCodeRequest：code 必填，stdin 可选） |
| POST | /syntax-check | 语法检查（SyntaxCheckRequest：code，返回错误列表） |

## 4. 代码执行器设计

文件：`api/tools/algorithm_practice/services/executor.py`

### 4.1 执行模型（execute_python）

```
用户代码 → 写入临时目录 solution.py → subprocess.run(线程池) → 捕获 stdout/stderr/exit_code/耗时
```

- **线程池执行**：`await asyncio.to_thread(_run_subprocess, ...)` 调用阻塞式 `subprocess.run`
- **为什么不用 asyncio.create_subprocess_exec**：uvicorn 以 `reload=True` 启动时进入 `use_subprocess=True` 模式，在 Windows 上使用 `SelectorEventLoop`，该事件循环**不支持** `create_subprocess_exec`（会抛异常）。`subprocess.run` 在独立线程中运行，兼容所有事件循环类型（Proactor / Selector / uvloop）
- **解释器**：`sys.executable`（当前后端解释器，`uv` 管理的 venv python）
- **隔离模式**：`-I` 标志（等效 `-s -E`），不加载用户 site-packages，忽略 PYTHON* 环境变量，标准库仍可用
- **超时**：`subprocess.run(timeout=10)`，超时由 subprocess 内部 kill 子进程，捕获 `TimeoutExpired` 返回 `timed_out: true` 与部分输出
- **stdin**：`input=stdin.encode("utf-8")` 管道传入
- **工作目录**：临时目录（`tempfile.mkdtemp(prefix="algo_run_")`），`finally` 中 `shutil.rmtree` 清理

**返回结构：**
```json
{
  "stdout": "...",
  "stderr": "...",
  "exit_code": 0,
  "duration_ms": 59,
  "timed_out": false
}
```

### 4.2 语法检查模型（check_syntax）

- 用 `ast.parse(code)` 做纯语法校验（不执行代码）
- 合法/空代码返回 `[]`；捕获 `SyntaxError` 提取 `lineno/offset/end_lineno/end_offset/msg`
- 边界兜底：null 字节等抛 `ValueError`、深层嵌套抛 `RecursionError`，统一转为首行错误提示
- 行列约定：**1-based**（与 Python SyntaxError offset 一致），由前端换算为 CodeMirror 绝对位置
- 该函数为同步纯函数，直接在事件循环中调用，无需线程池（ast 解析开销极小，毫秒级）

## 5. 前端设计

### 5.1 技术选型

| 项 | 方案 |
|----|------|
| 框架 | Vue 3.5 + TypeScript + Element Plus |
| 状态管理 | composable 模式（模块级 ref 单例，无 Pinia），同 useBookmarks 模式 |
| 代码编辑器 | CodeMirror 6（复用项目已有包，加装 @codemirror/lang-python、@codemirror/lint） |
| Markdown 渲染 | 复用 `doc_tools/md_reader/renderMarkdown.ts` 的 `renderMarkdownHtml`（markdown-it + highlight.js + DOMPurify） |
| 构建代理 | vite.config.ts 中 `/algorithm/admin` → `http://127.0.0.1:8000` |

### 5.2 导航与路由

- **工具注册**：`ui/src/config/tools.ts` 新增顶级模块 `algorithm`（图标 Cpu，紫色渐变 accent），homePath `/algorithm/problems`
- **路由**（`ui/src/router/index.ts`，AppLayout children 下）：
  - `/algorithm` → redirect `/algorithm/problems`
  - `/algorithm/problems` → `ProblemListView.vue`（题目列表）
  - `/algorithm/practice?id={problem_id}` → `PracticeView.vue`（练习页）

### 5.3 状态管理（composables/useAlgorithm.ts）

单一 composable 函数，导出类型与模块级单例 state：

- **类型**：`AlgorithmTag`、`ProblemListItem`、`ProblemDetail`（extends ListItem + description/solution_code/thought）、`ExecuteResult`、`SyntaxErrorItem`、`ProblemFilters`
- **State**：`problems`、`problemsLoading`、`tags`、`tagsLoading`、`executing`（防重复提交）
- **函数**：
  - 标签：`listTags` / `createTag` / `updateTag` / `deleteTag`（变更后自动刷新列表）
  - 题目：`listProblems(filters)` / `getProblem(id)` / `createProblem` / `updateProblem` / `deleteProblem` / `setProblemTags` / `saveSolution(id, code, thought)`
  - 执行：`executeCode(code, stdin)`（内部维护 executing 标志）
  - 语法检查：`checkSyntax(code)` → `SyntaxErrorItem[]`

### 5.4 题目列表页（ProblemListView.vue）

- **布局**：顶部工具栏（搜索框 + 新建按钮 + 标签管理入口）→ 标签筛选 chips 条 → 题目列表 → 新建/编辑对话框
- **搜索**：标题关键字，防抖调用 `listProblems({ q })`
- **标签筛选**：chips 多选，多标签交集筛选（选中标签高亮，点选/取消）
- **排序**：下拉切换「最近更新 / 最早更新 / 最近创建」
- **列表项**：标题 + 标签 chips + 更新时间；悬浮（hover）显示 `description_preview` 摘要
- **新建/编辑对话框**：标题（必填）+ Markdown 描述 textarea + 标签多选；编辑时先 `getProblem` 拉取完整描述
- **标签管理对话框**：展示全部标签（色块 + 名称），支持新建、改名、改色、删除
- **删除确认**：ElMessageBox 二次确认

### 5.5 练习页（PracticeView.vue）

**布局（左右分屏，可拖动分隔条）：**

```
┌─────────────┬──────────┬──────────────────────────┐
│  工具栏：返回 标题 ● 未保存 │          │ 主题/复制/重置/保存     │
├─────────────┼──────────┼──────────────────────────┤
│  题目描述(Markdown渲染)│ 分隔条 │ CodeMirror 编辑器        │
│  解题思路 textarea    │ (可拖动) │ (Python 高亮 + lint)     │
│             │          │  stdin 折叠区             │
│             │          │  运行按钮 + 退出码/耗时      │
│             │          │  输出区 (stdout/stderr)    │
└─────────────┴──────────┴──────────────────────────┘
```

**分屏可拖动分隔条：**
- 左面板 `flex-shrink: 0` + `flexBasis: {ratio}%`，右面板 `flex: 1 1 0` 自动填满
- 拖动范围限制 20% ~ 80%，拖动时 body 加 `user-select: none` 防文本选中
- 比例持久化到 localStorage（key：`algo-practice-left-ratio`，默认 0.4）
- 双击分隔条重置默认比例
- 拖动结束调用 `editorView.requestMeasure()` 触发 CodeMirror 重排

**CodeMirror 编辑器（buildEditor）：**
- 扩展：`lineNumbers`、`highlightActiveLine`、`drawSelection`、`history`、`bracketMatching`、`python()`、`lintGutter`、`pythonLinter`、`keymap`（default + history + indentWithTab）、`lineWrapping`
- **主题切换**：`Compartment` 动态 reconfigure `oneDark`（默认暗色）与空数组（浅色），工具栏月亮/太阳按钮切换
- **语法错误检查（pythonLinter）**：
  - `linter(source, { delay: 600 })` 600ms 防抖，输入停顿后自动检查
  - source 内请求序号（`syntaxCheckSeq`）防止过期响应覆盖最新结果
  - 错误转换：后端 1-based 行列 → `view.state.doc.line(...)` 换算为 CodeMirror 绝对 `from/to`
  - 展示：行内红色波浪线 + 行号旁 lint 图标 + 悬停显示错误消息
  - 网络/后端异常时静默返回空数组，不干扰编辑
- **保存**：工具栏「保存」按钮同时提交 `solution_code` + `thought`（走 PUT /problems/{id}），成功后清除脏标记
- **脏标记**：代码/思路改动时显示标题旁圆点，提示未保存
- **stdin**：折叠面板，textarea 输入，运行时随请求提交
- **运行**：按钮 loading + disabled 防重复提交；结果区展示 stdout/stderr、退出码（0 绿/非 0 红）、耗时、超时标记

**其他交互：**
- 复制代码（navigator.clipboard）
- 重置代码（确认后清空编辑器）
- 返回列表；`watch(problemId)` 切换题目时重建编辑器

## 6. 安全与限制

- **代码隔离**：`subprocess.run([sys.executable, "-I", tmp_file])` — `-I` 隔离模式，不加载用户 site-packages 与 PYTHON* 环境变量
- **超时保护**：10 秒硬超时，subprocess 自动 kill，防死循环拖垮服务
- **已知限制**（个人工具可接受范围）：
  - 用户代码仍可访问网络、文件系统（未做 Docker 级沙箱）
  - 无内存限制、无系统调用过滤
  - 单份代码无版本历史，覆盖式保存
- **认证**：走项目统一 `ConsoleAuthMiddleware`，与其它管理接口一致

## 9. 已知问题与后续优化方向

- 代码执行无内存/资源限制，如需更严格隔离可迁移 Docker 容器方案
- 题目无难度等级、来源链接、测试用例字段（用户明确不需要，可后续按需扩展）
- 单份代码无历史版本，可扩展为快照机制记录多次尝试
- 列表目前只按标题搜索，可扩展为描述全文搜索
- 执行器未做并发上限，极端场景可加信号量限制同时运行的子进程数
